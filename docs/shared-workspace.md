# 共享工作区页面

实现版本：0.4.0。范围是 Athena 中当前活动的 BrowserOS 页面，不是 Mac 桌面远控。双方看到并操作同一个 BrowserOS 标签页；受邀端不会重新加载一份目标网站。

## 使用

1. A 打开需要共享的 HTTP(S) 页面，点击浏览器标题栏的 **Share**。填写称呼，选择双方可互通的局域网或 VPN 地址，然后开始共享。正在录制时需先结束录制；正在执行的 Agent 会停止。
2. 把邀请链接发给 B。邀请有效期为 10 分钟；生成新邀请会使旧邀请失效。撤销邀请会取消仍在等待确认的加入请求，已确认成员需单独移除。
3. B 用桌面浏览器打开链接。服务使用本次共享的临时自签 HTTPS 证书；首次连接需通过可信渠道与 A 核对 SHA-256 指纹后，由 B 决定是否继续访问。A 的「连接与证书」可查看指纹。无需导入根证书或更改系统钥匙串。
4. B 填写称呼、请求加入。A 根据称呼和显示的身份编号确认是本人，选择「仅查看」或「可操作」。称呼是自行填写的显示名，不是第三方账号认证；允许加入后，身份绑定随机会话凭据，后续输入和记录不能自行改写为 A。
5. 获得「可操作」权限后，B 可请求操作；A 点击「交给 B 操作」。一次只允许一人控制，A 可随时收回。另一方继续看实时画面。B 可以点击、键盘/中文输入、粘贴本人剪贴板文本、滚动、同站点导航，以及使用同一套元素检查器、HeroUI Pro / A2UI 控件修改和撤销自己的预览。
6. 「停止共享并保存记录」或「结束共享并查看」会关闭连接、撤销凭据并保存操作记录。A 在「操作记录」查看按时间排列的双方操作，或导出 JSON。B 在本次浏览会话内也可以查看收到的记录；不重新执行网页动作。

当前站点以 origin（协议、主机和端口）为界。B 不能通过分享入口切换到其他本机服务；需要另一个站点时由 A 在地址栏打开。共享期间不切换/新增其他标签页，不执行 Agent，不开放文件选择或下载。DOM 预览仍只影响当前页面，刷新后恢复；不等于修改或保存源码。

## 连接边界

- 服务绑定 A 选择的 IPv4 接口和系统分配的临时端口，使用独立 HTTPS/WSS 端点。CDP、Neo、IPC、宿主 CLI、文件和钥匙串接口没有转发给 B。
- 支持同一局域网，或已有 VPN 能让双方直接访问所选地址的网络。Mac 必须开机且 Athena 正在运行。路由器的客户端隔离、macOS 防火墙或 VPN 路由仍可能阻止连接。
- macOS 出现 Athena 的入站连接请求时，需要用户允许该应用接收连接。应用不修改防火墙规则、不关闭防火墙、不创建端口转发。
- 没有部署公网中继，也没有内置 NAT 穿透。普通跨互联网邀请不保证可达；本次没有使用或购买外部服务器。后续若需要中继，应先确定具体资源、域名、TLS 与运营责任，再单独授权部署。
- 分享最长 8 小时；这是连接凭据的有效期，不是开发目标的截止时间。断开的身份可在 10 分钟内重连，控制权在断线时归还 A；同一凭据不能同时在两个窗口使用。已移除成员的旧凭据不可恢复。

## 一致性、权限与性能

- 正常捕获复用同一条 `Page.screencastFrame`。不可见 iframe 更新文档但没有产生绘制时，由同一个 BrowserRuntime 补取一次当前视口画面，校验页面代次后仍分发给所有客户端；如果捕获期间页面变化则丢弃补帧。不会为每位参与者启动独立捕获。同一帧的传输编码在受邀者间复用，每位受邀者最多一帧在途、一帧待发；收到解码确认后发送最新帧。慢客户端不影响 A 的 CDP 帧确认，不积压历史画面。
- 接收端和每个连接最多 64 个未完成请求，浏览器执行队列最多 128 个常规命令。队列满时明确拒绝新命令，不静默重放点击或文本。0.3.2 的同位置/方向/修饰键滚动合并保留，额外以操作者和控制权代次分隔；已接受的增量不跨人合并。
- 输入绑定服务端认可的参与者、控制权代次、已经解码确认的画面、标签、页面代次和原生 CSS 视口。导航、iframe 文档变化、主机缩放或控制权变化后，排队的旧输入在实际执行前再次校验。输入法提交还绑定开始输入时的页面和控制权代次，不把旧页面的组合文字写入替换后的文档。过时画面被拒绝；只改变 B 窗口尺寸不会改变 A 的权威视口，B 以等比留边映射坐标，DPR 不重复乘算。
- 断线、移除、降级、停止共享会撤销未执行输入。已经发送给网页的动作不能回滚；重连后不自动重发结果未知的动作。接管时释放已按下的键/鼠标，不补发点击，并将已应用的连续预览按原作者结算。
- 预览 ID 有独立作者。不能续写、提交或撤销另一个人的预览；如果其他参与者随后修改了同一元素，也不能用较早撤销覆盖对方的结果。
- 操作记录包含稳定参与者 ID、显示名、时间、页面/目标、输入/修改和控制权交接。滚动防抖保存触发时的作者，交接时刷新旧作者事件。长记录每 1800 步分段保存，避免原有 2000 步上限静默截断；完整分段保存在 A 的工作区。
- 记录沿用 `workspace.json`，参与者字段为可选扩展，旧数据无需迁移。分享凭据只在主进程和受邀浏览器的 `sessionStorage` 中暂存；临时证书私钥在加载后删除，不写入工作区记录。记录中的敏感输入沿用原有遮罩，但实时画面会显示网页当前内容，应只邀请可信任的人。

## 验收证据

已完成 0.4.0 独立应用的同机两进程（Athena A + Chromium B）端到端验收，分别经过 loopback 和实际局域网 IPv4 接口的 HTTPS/WSS 服务。测试页面由真实 BrowserOS 驱动，验证 B 输入保存、A/B DOM 修改、双人撤销隔离、断线重连、窗口缩放、Retina 坐标、权限收回和操作归属。协议测试额外验证未确认成员不接收页面、越权动作、过期/撤销邀请、旧帧、慢客户端、启动取消、写盘失败后的关闭，以及旧连接结果不能串入新连接。

开发态 Electron 曾因系统等待入站确认而超时。独立打包的 Athena 已通过局域网接口测试，本次未更改防火墙规则。这里验证的是同一 Mac 上两套独立客户端经真实局域网地址连接，物理第二台设备、VPN 和跨互联网链路未验证。

实测方法：对同一有 120 个条目的页面，通过 A/B 实际界面以 120 Hz 定时目标、持续 5 秒注入滚轮事件（实际包数记录在 JSON 中）；计数的是嵌入图片成功 decode 且仍为当前图片的不同内容帧，不是配置帧率。记录停手后浏览器队列屏障和两个原生渲染帧完成的时间。待主机尺寸和双方解码视口一致后开始测量。

| 本机双客户端场景 | A 解码 fps | B 解码 fps | 停手后排空 ms | B 操作确认 P95 ms |
| --- | ---: | ---: | ---: | ---: |
| A 滚动，未选中 | 58.4 | 58.4 | 55.2 | — |
| A 滚动，已选中 | 58.4 | 58.2 | 53.6 | — |
| B 滚动，未选中 | 58.3 | 58.3 | 42.4 | 35.7 |
| B 滚动，已选中 | 58.4 | 58.4 | 51.1 | 33.8 |
| A 滚动，另有不确认帧的慢客户端 | 58.3 | 58.3 | 46.4 | — |

本轮实际注入 107.3–111.7 包/秒，每个 B 输入包均收到确认，所有场景的滚动距离误差不超过 2px。首次输入后的首个新解码帧，A 为 17.8–23.8ms，B 为 20.9–26.0ms；这是应用层画面更新时间。

结果来自 `test-results/sharing/packaged-lan-e2e.json`，loopback 独立包复测见 `packaged-loopback-e2e.json`。测试没有宣称跨设备网络延迟等于这些同机数字。A、B 和权威网页的实际 `devicePixelRatio` 均读取为 2；B 窗口尺寸覆盖 1200×800 和 760×620，坐标单元测试另覆盖上下/左右留边和拒绝图像外输入。

共享关闭后，对 0.3.2 的 1100px 宽、120 项页面继续运行原滚动回归：0.4.0 独立包未选中/选中分别为 56.7/56.8 fps，帧间隔 P95 28.8/31.0ms，停手后排空 58/39ms，滚动距离断言通过。见 `test-results/sharing/packaged-local-scroll.json`。该宽页与共享测试页不同，不作两张表间的直接帧率对比。

本地构建为 `release/sharing/mac-arm64/Athena.app`，版本 0.4.0，bundle ID 仍是 `app.agent.workbench`。构建、类型检查和 ad-hoc 深度签名校验通过；没有 Apple 公证、源码推送或公网发布。

```sh
npm run typecheck
npm test
npm run build
# 受控本机双进程测试，不更改防火墙；不作为局域网可达证明
ATHENA_SHARE_LOOPBACK=1 ATHENA_SHARE_PERF=1 npm run test:sharing
# 默认选择非 loopback 网卡，需先允许 Athena/Electron 的入站连接
ATHENA_SHARE_PERF=1 npm run test:sharing
# 已构建的独立应用也运行同一验收
ATHENA_SHARE_APP='/absolute/path/Athena.app/Contents/MacOS/Athena' ATHENA_SHARE_LOOPBACK=1 ATHENA_SHARE_PERF=1 npm run test:sharing
```

输入编辑快捷键采用 Chromium 的固定 `selectAll` 编辑命令，未开放任意命令字符串。协议来源：[Chrome DevTools Protocol · Input.dispatchKeyEvent](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/json/browser_protocol.json)。
